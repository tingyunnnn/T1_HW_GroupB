# 專案核心文件使用指南 

本專案將所有的開發規範與規格匯整為三大核心檔案。以下說明這三個檔案的用途以及彼此的協作方式：

## 📁 檔案清單與分工

1. **`software-spec.md`（軟體規格書與開發規範合集）**
   - **內容**：包含完整的軟體規格書（系統需求、選項代碼、API 介面與欄位格式）、`AGENTS.md`（代理規範與修改前後工作流）以及 `SKILL.md`（API 變更與例外處理流程）。
   - **用途**：作為專案的核心依據。在動手寫程式或修改功能前，**必須先閱讀此檔案**以確保符合業務邏輯與驗收標準。

2. **`AGENTS.md`（AI 開發代理規範）**
   - **內容**：定義 AI Agent 在本專案中的角色（後端與 API 開發 Agent）以及「修改前」、「修改後」的標準作業程序與回報格式。
   - **用途**：當由 AI 協助進行程式碼開發、重構或維護時，AI 必須嚴格遵循此規範進行影響範圍評估與驗收回報。

3. **`SKILL.md`（標準工作流程技能）**
   - **內容**：封裝了處理 API 變更、檔案上傳或例外流程的標準步驟（讀規格 ➡️ 找影響範圍 ➡️ 建立測試 ➡️ 分類問題）。
   - **用途**：當遇到功能擴充、API 調整或異常排查時，執行標準化的高效處理步驟。

---

## 🛠️ 開發與協作工作流程

當您準備進行程式碼修改或新功能開發時，請依照下列步驟使用這些文件：

1. **第一步（查閱規格）**：
   - 打開 `software-spec.md`，確認本次異動所涉及的地點代碼、API 路由、請求/回傳 JSON 格式以及狀態驗證規則。
2. **第二步（遵循代理規範）**：
   - 依照文件中的 `AGENTS.md` 規範，先列出受影響的檔案與 API 範圍。
3. **第三步（執行標準技能）**：
   - 透過 `SKILL.md` 定義的 4 步驟（讀規格、找影響範圍、建立測試、分類阻擋與提醒事項）執行開發。
4. **第四步（驗證與回報）**：
   - 執行單元測試或瀏覽器測試，並依照回報格式輸出檢查結果與測試案例。
