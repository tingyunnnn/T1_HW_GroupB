# API 變更與工作流程處理器

## 何時使用
- 當遇到 API 變更、檔案上傳或例外流程時。
- 當需要評估系統或需求修改的影響時。

## 執行步驟
1. **讀規格**：仔細審閱需求與規格文件。
2. **找影響範圍**：列出所有受影響的檔案、API 與資料格式。
3. **建立測試**：撰寫單元測試或瀏覽器／整合測試案例來驗證變更。
4. **分類問題**：
   - **阻擋問題（Blockers）**：必須在繼續進行前優先修復。
   - **提醒事項（Reminders）**：必須交由人工確認。

## 輸出
- **檢查結果**：受影響元件與程式碼檢查的摘要。
- **測試案例**：新建立或執行的測試案例。
- **人工確認事項**：需要人工審查與確認的項目。
